# ETF 自动发现流程

现行政策：`workflow_v15_reliable_progress_20261003`。本页为当前运行规范；版本沿革见[历史存档](archive/20261003/ETF_AUTORESEARCH_PROGRAM.md)。固定人口、时点和数值条件以 [IC_MINING_RULES.md](IC_MINING_RULES.md) 为准。

输入是已批准且可用的 profile 与历史定义；输出是可复算公式及冻结方向下的 signed Rank IC、HAC t、有效日数、窗口和失败原因。工程通过要求时序、源码、输入及结果证据一致；候选 IC 为负也可正常完成。结果属于已见历史发现。

## 开放探索与角色

Luna `gpt-6-luna` 规划和实现，Sol `gpt-6.1-sol` 在开标签前审核公式与源码。统一生产 CLI 只接受 `--mode open`，默认每轮最多 4 条，可设 1–8 条；单候选调用记作单次试验，不重称多候选轮。

提案前查正式库和自适应库的定义、公式与结果。每条明确问题、输入、公式、窗口、方向、所选 profile 和与已有候选的差异。历史家族是参照，不是准入名单；不设新旧配额、每家族一条、来源轮换或家族暂停门。同家族可提出不同假设，不为填满名额重复无新信息的定义。

每轮最多两次规划请求，不足则少跑。技术审阅核对输入含义、可用时点、数学公式及实现一致性；旧变体或语义相近本身不构成拒绝理由。输入必须来自所选批准 profile；候选不得自行读取文件、下载数据、跨来源混用面板或读取标签。

## 最短执行路径

1. 读取累计定义与输入合同，冻结批次 ID、预算和本轮公式；保留所有规划请求及决定。
2. 审核公式后实现候选，保存每条源码。`score(panels)` 返回同索引、同 ETF 列的原始数值 DataFrame，评价器只乘一次 `DIRECTION`。
3. 做静态与合成输入检查，再审源码。标签前实现缺陷最多修正一次；原稿、修订和审核分别保存，不能借修复改变公式、方向或窗口。
4. 用截至冷线的真实特征做因果前缀与可排名日检查。零完整八组可排名日记结构失败，不计一次正式 IC 评价；少量有效日不增加拒绝门。
5. 同输入、同合同、有符号分数、完整索引及 ETF 有效掩码完全一致的定义引用旧结果。其他候选直接运行固定 IC 评价，无需无关父基线；高排名相关仅作诊断。
6. 核对预检与正式评价的源码、输入合同及分数哈希，封存完整结果。更新自动库，分别报告完整轮数、计算轮数、候选数、IC 数与请求错误。

数学模板服从冻结公式：`conditional_ols` 仅指按布尔条件选样本的单解释变量、含截距回归；多元回归、偏系数和残差化用相应自定义实现。模板不适配时记录 `math_kernel_binding.requested/effective`，不能为套模板改写公式。模板被调用时嵌入精确源码并封印。 修复请求只展示候选可编辑部分，已封印且与模板完全一致的基础函数从请求中的原稿移除，由控制器重新嵌入；完整原稿仍保留，返回稿若自定义或修改该函数仍按精确校验拒绝。

精确重复需要可核对的来源、输入合同与有效日期；源码 AST 相同或相关性高均不够。缺少完整证据不能自动跳过计算或宣称独立性。有效负 IC、弱正 IC、覆盖不足的数值 IC 全部留存，不自动翻向。

## 启动与停止

仅在已有授权预算内使用新 campaign ID。示例中的 ID 和轮数须替换为实际批次信息：

```bash
.venv/bin/python frameworks/etf_rotation/scripts/research/run_etf_autoresearch_campaign.py \
  --campaign-id NEW_AUTHORIZED_ID --rounds 3 --candidates-per-round 4 \
  --mode open --profiles all --model gpt-6-luna --reviewer gpt-6.1-sol
```

`--profiles all` 选择所有已批准且文件可用的来源；可指定 `daily` 或批准来源的子集。来源的公式、可用时点、陈旧规则和 vintage 局限保存在 manifest。人口仍固定为 14 ETF / 8 组，冷线仍为 2026-03-24。

达到批次预算即结束。普通技术拒绝、负 IC 或真实空提案可以继续剩余轮次；公共数据故障、超长请求、传输失败、未知异常或中断立即暂停并保存已有提案，不能记为空轮消费预算。规划格式错误最多一次标签前修正。

同政策安全恢复点可用原命令加 `--resume`：复用冻结计划与成功请求，完整结果只补汇总。已开标签但未完整结束、封印不一致或阶段不明时暂停排查。旧政策批次只读核查，不用 v15 续写旧结果。具体预算与恢复条件见[运行说明](ETF_LUNA_DAGU_OPERATIONS.md)。

## 结果与边界

逐条报告公式、方向、IC、HAC t、n、实际信号首末日及证据路径。累计与本批分别报告；基本筛选、多重检验、冗余/增量、收益和独立认证分栏。`ic_recorded` 与 `parent_replaced` 分开，未替换父版本不表示没有 IC。

自动库与正式库的路径及更新方法见[IC_INVENTORY.md](IC_INVENTORY.md)。自动试验不增加正式 PLAN 登记数；正式 promotion 仍需对应输入支持、源码冻结和原入口审阅记录，外部源自动试验不能通过缺少对应输入的旧正式 runner 登记。

逐轮计划、源码、模型请求、尝试、完整结果和原始 summary 保留原位。旧单候选爬山、配额/家族暂停与来源调度的执行代码及测试已移入[代码归档](../legacy/autoresearch_20261003/README.md)；当前 Python 接口也只接受开放模式。历史读取、正式复算、标签时序与封印校验仍保留。月度前向 v4 单独运行，不能把自适应历史结果当作独立确认。
