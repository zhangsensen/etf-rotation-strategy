# ETF IC 挖掘规则

现行范围与数值合同；整理日期 2026-10-03。本次只合并现行条款，不改人口、标签、方向或数值条件。历史条款与调度版本见[清理前存档](archive/20261003/IC_MINING_RULES.md)。自动执行采用 [v15 开放流程](ETF_AUTORESEARCH_PROGRAM.md)，不设旧家族准入、新旧配额或家族暂停门。

有符号截面 Rank IC 是唯一主评价。公式、方向、IC、HAC t、有效日数、窗口逐条交付，累计与本批分别报告；收益、成本、多重检验、冗余、增量和认证不能成为 IC 留存附加门。不设预期 IC ≥ 0.1 的提案门，不为普通挖掘增加重复审签。

主发现视图为 `POSITIVE_IC`（IC≥0.01）、`NEGATIVE_IC`（IC≤−0.01）、`NEAR_ZERO`（|IC|<0.01）、`UNCOMPUTABLE`（无法计算或证据无效）。0.01 仅是此显示视图的分档线；精确 signed IC、数学正负、覆盖和稳定性另列。有效但稀疏的 IC 保留，负 IC 不自动翻向。旧 HAS_IC/NO_IC/PENDING 和基础筛选仅作独立诊断。

每条正式标签评价前检查固定八组是否存在共同可排名日。零可排名日记结构失败，不计入已评价候选；少量有效日不加拒绝门。正式与自适应结果分别查询，入口见[因子库](IC_INVENTORY.md)。

## 1. 当前交付与禁止项

ETF与个股是两个独立项目。本规则仅适用于当前ETF项目，不约束或改写个股项目的方法论。
两者的人口、配置、授权、搜索预算、评价面账本和结果分别维护，不并账、不合计因子数、不互认验证结论。
个股因子不进入ETF结果；ETF研究失败不能自动转去挖个股。跨项目复用或切换须用户明文授权。

交付：可计算的因子公式、方向、逐日分数、IC预测证据、适用范围、重复性和失败原因。
当前不是策略验收：不要求因子先通过TopK收益门才保留IC线索，不调仓位、止损、择时、换手或成本参数。
收益数据可以旁报，不能拿其失败覆盖IC结果；本阶段也不宣称净收益、交易许可或认证。
不能以“缺少未见历史”阻止已见历史上的发现；同样不能把发现叫作独立确认。

## 3. 数值条件与结果层级

### 时间面先于数值门

- 方向在研究开始前冻结的候选，可把2025+全段作为已见历史线索统计；仍不构成认证。
- 使用2025标签确定方向的候选，2025只负责定方向，后续统计只读2026历史单段；不能把两年合并t，也不能把已见2026称为独立确认。
- 公式或模板在看过2026后继续迭代的候选，2026标记`SEEN_2026_ADAPTIVE_NOT_CONFIRMATION`；即使t通过也只是历史线索。
- 看见负IC后翻向的候选标记`POST_RESULT_REVERSE_NOT_CONFIRMATION`，不得计作独立方向。
- 所有因子分数在排名和top-K边界先统一规范为12位有效数字（相对精度；绝对12位小数会把量级约1e-11的因子截成假并列，2026-09-23修正），再用平均秩处理并列；原始分数保留审计。

以下是当前冻结筛选条件，不是“所有因子通用真理”；调整必须事前另记实验，不能为已出结果降门。

| 层级 | 条件 | 未满足如何处理 |
|---|---|---|
| 工程有效 | 人口/时序/输入校验、前缀不变和截后扰动通过；源码与输入哈希一致 | 实现失败，结果不进入有效因子判定 |
| 覆盖 | 旧配置有效IC日数 n ≥ 360；显式 `cold_250_v1` 新候选 n ≥ 250 | COVERAGE_INSUFFICIENT，保留数字，不宣称机制无效 |
| 基础IC | 按冻结方向IC均值 ≥ 0.01；日历HAC t ≥ 2（lag=10）；日历5日块t ≥ 2 | NOT_SUPPORTED_THIS_SCREEN，保留失败项 |
| 稳定性 | 2025和2026各至少40有效日且IC均值均为正；剔任一组后IC均值均 > 0 | 不入基础IC线索；不自动换方向、年份或分组 |
| 基础IC线索 | 覆盖+基础IC+稳定性 | IC_LEAD_ONLY，不要求B8超额过门 |
| 多重检验 | 单边正态近似p ≤ 0.05 / 事前登记检验族预算，独立字段报告 | 未过校正，仍保留基础IC线索但不称统计确认 |
| 非重复性 | 双方共同有效日期上，逐日截面秩相关绝对值的均值 < 0.7 | REDUNDANT注记；不作为新的独立发现，也不抹掉原IC统计 |
| 两腿新增信息 | 当前入口若为交互/条件复合，对每条单腿的共同日IC差均值 > 0、HAC t ≥ 2；全窗共同日数≥360，2026历史单段≥120 | 不声称复合式新增信息；收益差只旁报。两个原始序列的滚动相关系数按一个原子机制处理，不自动拆成两腿 |
| 反向观察 | 原方向IC ≤ −0.01、HAC t ≤ −2、块t ≤ −2 | REVERSE_WATCH_NOT_VALIDATED；覆盖状态另列，不自动视作反向成立 |

对已有货架与朴素基线的比较必须用共同日期；未完成则标NOT_TESTED，不能用两个t的大小代替配对差检验。
相关阈值采用mean(abs(日IC相关))，不是abs(mean(日IC相关))，二者不得混报。
八组不是八个独立观测；非重叠H5块也不自动独立。t值不能仅由样本行数解释。

收益字段另报均值、HAC t、B8/B14对照和覆盖情况。旧`screen_pass`/`shortlisted`是联合门兼容字段，
不是主发现计数；主视图读页首方向分类，`ic_candidates`、`ic_budget_candidates`、`reverse_watch_candidates`分别作为诊断。
运行verdict显式给出`primary_evidence_field: ic_candidates`及旧shortlisted的兼容语义。
旧`summarize_etf_group_campaign.py`只供历史批次汇总，不能拿其联合通过数代表当前IC发现数。
负向记录原本在全量结果里；新增的是显式观察清单，不允许谎称旧结果丢失。

## 4. 机制提案与搜索纪律

1. 可从机制假设出发，也可在已见发现面比较同日未来领先/落后组的D日状态，再提出可证伪机制。
   未来收益只进入标签/评分；学习出的差异仍是事后发现，不包装成先验。
2. 每条说明信息来源、公式、窗口、预期方向、历史标准化和截面排序顺序、与已有候选的区别。
3. 先查结构有效性。6个单成员组不能与多成员组的常数/不同尺度“成员一致性、集中度、熵”直接竞争。
   设计必须在看标签前解释单成员定义与可比性，不能跑完再补理由。
4. 不为凑条数在没有新信息时仅换窗口或名称重跑同一定义，不事后调K/H/分组/方向，
   不用等权相加/拟合权重/投票包装单因子。旧家族的非等价假设可按开放流程研究，说明差异即可。
   rank_spread或rank_interaction须定义具体机制；两腿增量限制新增信息声明，不成为 IC 留存门。
5. 反向可成为后续假设，但须明确“由已见负向结果提出”，登记新方向尝试；同面再跑只算发现/复现。
6. 每批先定预算；自动发现按轮冻结清单，每轮最多8条，不必凑满；这是提案上限，不是新增8条授权。
   公式、方向、窗口、算子/分组改变、看到收益后的筛选尝试均记录；失败也保留。

原96预登记与追加8的记录不清零。复算pilot不增加公式数；工程失败是否揭盲、是否改公式分别记录，
源码版本数与统计假设数分栏，不能悄悄互换。至少约60次额外未完整登记搜索及更早搜索仍是证据债。
当前累计检验族未知；96/104均只能标相应历史批次的条件诊断，不称全球校正，不据此认证。

## 5. 角色、冻结和开始条件

- 用户：决定目标；扩人口、改分组/标签/主裁判、进入策略或交易需明文授权。
- master：在已授权发现范围内确定本批问题、上限和参照，审核结构与重复性；批准后才允许计算新结果。
- Luna：先提案与实现测试，收到master确认后冻结PLAN再运行；不自行改门、扩池或用另一入口绕过限制。
- 写文件分工：独立任务目录；master合并/验收，禁止两人同时编辑同一文件。

启动一批前必须齐备：

1. 本批ID与预算；自动流程逐轮冻结候选清单、公式/方向/窗口、机制来源与停止条件。
2. 固定人口/分组/数据根、evaluation_start、标签时序、缺失处理、数值筛选与预算。
3. 评价面标PREVIOUSLY_SEEN_NOT_OOS，原始及累计搜索状态，失败/反向/重复的记录路径。
4. master审签记录及公式/配置哈希，源码与输入标识；先完成合成测试，再读取新候选结果。
5. 新输出目录必须不存在；预算不得超本批上限；产物仅本地，不覆盖旧PLAN或报告。

STOP条件：越界、前视、运行中版本变化、结构不可比、达到批次上限即停；普通统计失败记录后可完成本批其余候选。
批次结束必须交全量表与分层计数，不只报最强值或“0条”；是否继续下批由master根据新信息来源决定。
本次规则更新本身不启动运行、不新增预算、不要求等待前向数据才可提出新假设。

## 6. 前向评价对象：固定月度流程

不再把单条历史因子冻结两年作为主前向方案。冻结的是流程版本：固定14只、八组、候选公式库、
360个已成熟训练交易日、IC筛选门、最多2条、去重/两腿规则、D+2/H5标签和下一自然月评价。
每个月末只使用当时已经退出的标签选因子；选择结果封存后，评价下一月信号日期的组间日Rank IC。
评价标签未全部成熟前不得出月度结论。中途可以检查文件完整性，不得用评价月结果回写当月选择。

任何人口、分组、公式库、训练窗、筛选门或选择规则变化都产生新的`process_version`和合同哈希；
新旧版本不得合并统计。同一`(process_version, contract_sha256, freeze_month, evaluation_month)`只能记一次。
因子阶段只记录换手，不把成本作为IC通过门；成本与净收益留到策略阶段。
当前机器合同为`configs/etf_ic_monthly_factory_v4.yaml`，实现为`etf_ic_monthly_factory.py`。v3因排名取整修复在首次入账前被v4替代；20条候选目录与首次冻结月份不变。
v1、v2均未写入账本；v3恢复v1的20条候选目录。513100开盘停牌窗口与高溢价行情状态
共线，已见结果无法区分机械影响与真实状态，因此不得事后作为候选排除门。每月选择表对全部候选
统一旁报“剔除其回看窗口含停牌日后的IC/HAC t/样本数”，不参与选择。share族不在候选库并保留
数据质量降级；NAV族不在候选库，异常值仅在消费侧标记/屏蔽，不改只读数据根。
v4的流程生效日为2026-09-23，禁止倒签冻结2026-09之前的月份；首次冻结只能在2026-09月结束后执行，
并评价2026-10。月末前只允许准备输入和做合同校验，不得产生选择结果或账本记录。

## 7. 执行与能力边界

Luna 明确使用 `gpt-6-luna` 提案/实现，新增 Codex 审阅使用 `gpt-6.1-sol`。通常每轮 4–8 条假设，完整轮数、候选数与实际 IC 计算数分别记录。自动发现的标签前审阅、一次实现修正、错误暂停、完整性封印与进度核对见[执行规范](ETF_AUTORESEARCH_PROGRAM.md)。

当前八组入口已实现 IC/覆盖/条件校正/收益/反向/两腿字段分离、12 位有效数字平均秩、时间面隔离、输入根与人口检查、源码输入封印及动态时序测试。未声明 `cold_250_v1` 的旧入口仍按 360 日，已打开旧结果不按新门回判。

尚未具备所有入口统一的安全级 master 身份认证、跨入口授权/评价面/历史搜索总账、外部货架认证和原数据 vintage 认证。现有审签是流程记录与版本绑定，不能因文档存在就称以上能力完成。

正式历史 runner 的新日线机制批仍使用 `--approval` 绑定 run-id、配置/源码哈希、清单和预算；`prior_registered` 须核对 PLAN 与外部登记，不能每批重置。旧 next8 与错误重判入口已禁用。自动发现结果可直接交付 IC，不必先加入正式登记；两个库不相加冒充独立因子数。

[历史线索观察名单 v2](../configs/etf_ic_lead_watch_v2.yaml)为独立旁路，只报告成熟月份逐条 IC，不改变月度 v4 选择。份额交互在父分数结束后的新日期标不可计算，不能填零或复制旧分数。名单版本中的条数不等于当前累计线索数。
