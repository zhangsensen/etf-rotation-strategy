# ETF IC autoresearch：代理实验规则

目标：在固定 14 只 ETF、8 个经济组中发现可复算、具有组间未来收益排序信息的因子。评价仍为 D 收盘分数与 D+2 至 D+7 复权开盘收益的**原 signed Rank IC**；不改变 IC 算法、门槛、月度 v4 或现有账本。本循环是已见历史发现，不是独立认证或交易许可。

本程序借鉴 [karpathy/autoresearch](https://github.com/karpathy/autoresearch)：固定数据和评价器，只编辑一个候选文件；先跑基线，再反复提出改动、运行、记录、保留或回退。源项目每轮固定五分钟并用同一验证指标选择；ETF 历史会被反复查看，所以本程序不把试验中的改进当作独立验证。

## 家族多样性优先 v3（2026-09-26）

用户明确将家族多样性列为第一优先级。当前命令行执行 v6：每轮先由 Luna 规划不同的经济机制，写出与已有家族的区别并冻结计划，再分配给并行实现。允许提出新机制，不预设封闭的因子菜单；没有足够可辩护的不同机制时少做或停止，不用改窗口凑条数。

1. **一轮每家族最多一条。** master 在看标签前按源码和经济机制给出 `canonical_family`。不同名称、参数、权重或数据 profile 不自动构成不同家族；归到同一家族的重复槽位标记 `DIVERSITY_SKIPPED`，不进入本轮计算。家族归类是可审阅的判断，不等于统计独立证明。
2. **默认至少四分之三的名额用于探索。** `mixed` 每轮最多 `floor(条数/4)` 条旧因子改进，4条时最多1条，其余优先不同机制。显式 `refine` 用于专门改进，但仍一轮每家族最多一条，不填重复槽位。
3. **跨轮限制重复投入。** 自动 mixed/explore 模式暂缓最近两轮尝试过的家族；别名在历史中合并，工程失败和审阅拒绝也计入研究投入。显式 refine 可指定再研究旧父因子，但连续两次已算出的改进不如父因子时暂缓该家族改进，直到新的可用父版本重置记录。工程失败不被当作机制无效。
4. **IC规则保持原样。** 已算候选全部保留原 signed IC、HAC t、n、分年结果；重复度独立展示。原始family与审阅后的canonical_family同时入库，新增家族数与公式变体数分别看。

v3计划保存在每个campaign的 `plan_rNN.json`，断点续跑复用原计划。已结束v1/v2结果不修改；旧版本未结束任务不能用v3重新解释，需以新campaign-id继续并读取历史库。

## 审阅材料与家族衔接修复 v4（2026-09-26）

- 新家族规划显式排除正式库与本地已记录家族；已知名称在写代码前过滤，审阅后归回旧家族的探索候选不再重复计算。原始规划回复仍留本地，少于名额时不补变体。语义上的重复仍需独立审阅，名称过滤不代表已经证明独立。
- 审阅包同时提供冻结父源码、哈希、原始家族、计划中的规范家族和事前方向，以及所选输入的公式和可用时点契约。审阅者无需猜测面板名称的含义。
- 改进源码允许沿用父源码家族名称或使用已计划的规范名称，但方向不能改变，机制仍需审阅。被拒绝子候选的分类不会反向重命名父家族。
- 每轮冻结历史家族集合；断点续跑不会把本轮待审候选误判为历史重复。v4 不续写旧 v3 campaign，使用新编号，旧结果原样保留。IC 算法、人口、标签、门槛不变。

## 评分接口与上下文 v5（2026-09-26）

实跑出现了 `raise`、`lambda` 静态拒绝以及重复取反风险，因此将现有评分接口显式传给提案和审阅模型，校验器限制保持不变：`score(panels)` 返回原始经济测量值，由评价器统一乘一次 `DIRECTION`；改进同时保留父源码乘方向后的实际经济含义，不能只保留方向常量而删除原公式的负号。必须返回与输入同索引、同ETF列的数值DataFrame，不能用跨ETF列归约替代逐ETF计算。语法错误记录具体AST类型，缺失数据使用数值掩码，不用异常分支。规划输出的 `input_profile` 在结构化响应Schema中限定为本轮允许的枚举，说明文字只能写入机制说明字段。

规划和提案阶段使用压缩历史视图，保留全部家族和定义编号，将每条机制说明截到500字符并去除重复字段；规划阶段仅在文字公式足够明确时省略输入源码；分钟面板的说明仍较概括，必须保留对应源码，不能凭面板名称猜测含义。指定父源码、方向及提案所选输入契约仍完整提供。摘要只用于检索和提案，不代替独立审阅：审阅仍收到完整历史定义、候选源码和输入契约。模型请求保存在本地，可核对实际材料。

v5以新campaign编号运行，不重写旧失败记录，不因修复语法或提示而改动旧结果、IC算法、标签、方向或判定门槛。

## 持续发现闭环 v6（2026-09-27）

目标是交付可复算因子及原 signed Rank IC，轮数只记录研究投入。本节替代前述版本的连续两轮无计算停止、空计划停止和按历史家族名称永久拒绝；旧campaign与结果保持原样。

- 提案先写公式、方向、所需字段、最近旧候选及具体差异。字段公式与可用时点来自输入契约，覆盖/变化诊断只读取截至冷线的特征，不读取收益标签，不新增覆盖阈值。
- 普通拒绝、负IC和空轮继续消耗剩余轮次预算。空计划每轮最多一次替代规划，不用重复变体填满名额。公共数据或评价器故障暂停排查；候选缺陷与系统故障分开记录。
- 看标签前，语法、形状或字段实现问题最多修正一次并重新审阅。原稿和修订分别留存；公式假设、方向、人口不能借修正改换。任一标签已开启后不得修正同一实验，新的公式另开新试验。
- 审阅检查可计算性、数据时点、实际方向与计划一致性、完全等价重复。经济假设强弱是意见，不能以“预计不会有IC”取代实际计算；确实不表达声明方向或不实现计划的源码仍拒绝。
- 已知家族中的非等价探索候选只可在剩余改进名额内、存在可复算同家族父版本时转为改进；否则留待后续，不能伪称新家族。默认每轮最多四条、同家族最多一条、旧家族改进最多一条。
- 库中 `ic_recorded` 与 `parent_replaced` 分开。正负IC全部留存，未替换父版本不等于没有IC。报告计划/实际轮次、空轮、实际计算量、新家族与重复度、具体IC及父版本比较。
- 使用新campaign编号启动v6；断点续跑复用冻结计划、源码和审阅记录，已开启但未完整结束的计算不自动重跑，不覆盖历史实验。

验收先用三轮验证持续性、修正边界与落盘，再运行二十轮预算；不会要求试跑必须产生正IC。研究产出与工程通过分开汇报。

## 统一挖掘入口与命令

后续 ETF 自动发现统一从 `run_etf_autoresearch_campaign.py` 启动。旧日线、外部源脚本保留用于历史复算；不再需要按新家族新建挖掘入口。v1 单一最高 IC 的爬山循环保留为历史接口，命令行已转入 v6 持续发现工作流。

```bash
.venv/bin/python frameworks/etf_rotation/scripts/research/run_etf_autoresearch_campaign.py \
  --campaign-id etf_next_01 --rounds 10 --candidates-per-round 4 --mode mixed
```

默认每轮最多 4 条（可设 1–8，单条应称试验），Luna 先规划，再并行实现整轮候选，冻结源码后由独立 master 模型审阅，审阅通过才串行运行原 signed Rank IC 评价。`mixed` 以探索不同机制为主，少量改进已保留父因子；没有可复算父因子时先探索。也支持 `explore` 或 `refine`；指定 refine 但没有合格父因子时记空轮并继续预算，不计为一次实际计算。已完成的历史轮次不改写。

- **探索**：每条因子的正、负、近零、不可计算 IC 均写库。正 IC 可作为后续研究父因子，不要求超过不相关的参考因子，也不新增 HAC t 或收益门。
- **改进**：在同家族、同方向下与自己的父因子比较。共同有效日期完整一致且 signed IC 改善才替换该家族的父版本；未改善的候选仍保留源码及全部 IC。不同数据输入 profile 的父因子分别维护。
- **记忆**：每轮前读取正式库的定义/家族元数据与本地历史试验；不读取正式库冷线之后的 IC 给提案模型。重启新 campaign 会继续使用已有可复算父因子与失败记录，不需从零开始。若评价器更新，父源码在新评价器下重新计算参考结果，再比较，旧结果保持原样。
- **留痕**：整轮提案、审阅、源码哈希、数据 profile、父子关系、逐日 IC、HAC t、n、分年 IC 和失败原因均保存在本地。`runtime_outputs/etf_autoresearch_ic/library/library.csv` 与 `library.json` 是自动更新的跨 campaign 查询入口。数学 IC 与 `POSITIVE_IC/NEGATIVE_IC/NEAR_ZERO/UNCOMPUTABLE` 并列；不将描述分类叫作认证。
- **数据**：默认 `--profiles all` 允许使用所有已批准且文件可用的 profile；先确定家族机制，再选择所需输入；可用 `--profiles daily` 只挖日线，或用逗号列出 `us_sector,us_vix,us_style,ext_gold,ext_copper,ext_crude,ext_cnh,ext_hktech,ext_realrate,ext_coal,minute,share,nav`。输入适配器负责来源哈希和严格早于中国信号日的对齐。新增源必须先接入可用时点明确的适配器，候选源码不自行下载或读取文件。分钟、份额、NAV 沿用已有转换和可用时点/陈旧规则，并在原始读取层裁到冷线；数据质量和来源 vintage 局限保留在 manifest，不能当作发布时点已认证。
- **边界**：自动库是新的发现记录，原正式 PLAN 账本和历史库存保留，两个计数分别展示。正式登记仍用源码冻结的 promotion 入口；发现不必先登记旧正式账本才交付。外部源候选现阶段保存在自动库，正式 promotion 暂时拒绝，避免旧正式 runner 缺少该输入而误算。

完成指定轮数即停止；普通拒绝、负IC和空轮继续，公共数据或评价器故障暂停并保存错误。中断后先检查 `summary.json`，可恢复的标签前中断才在同一命令加 `--resume`：复用冻结提案，继续审阅和未运行的候选；已开启但未完整结束的评价标记 `PAUSED_SYSTEM_ERROR`，不会自动重跑。也可经明确安排用新 campaign-id 继续并读取历史库。运行不改工作区候选文件。此机制固定 ETF 项目；个股项目不随本次改造合并。

## 原挖掘与自适应迭代怎样接上

本节中的 `--parent-candidate`、`--baseline` 和唯一候选文件说明属于原单候选迭代接口，用于历史复算。当前 v6 统一入口使用上文的 `--mode mixed/explore/refine`，自动选取父版本，每条源码保存在各自 campaign 目录中；不要把旧参数直接传给当前 CLI。

原来的多家族批次负责 **0→1**：从不同信息结构提出定义，用正式库记录有 IC、无 IC、家族和失败结果。autoresearch 负责 **1→10**：选定正式库里一条有 IC 的父因子，在唯一候选文件中先精确复写它，跑出本地冻结基线，再沿同一家族试验计算方式、窗口或条件表达。每次试验仍只有一条公式，全部版本留痕；“10”表示更成熟的候选，不表示 IC 必须提高十倍或已获得十次独立验证。

启动父因子迭代时传 `--parent-candidate <正式库因子ID>` 和 `--baseline <本地父因子基线目录>`。程序会用最新正式库存找到父定义，并在共同日期核对本地基线与正式父因子的八组有符号秩完全一致；不一致就拒绝声称父子关系。后续各试验始终与这个固定父基线做共同日期比较，`decision.json` 写入父定义、冷线内基线 IC 和重复度。新家族若还没有父因子，可以不传 `--parent-candidate`，作为 0→1 探索，但不能称为某个旧因子的改进。

## 文件与边界

- **候选源码**：v6 写入 `runtime_outputs/etf_autoresearch_ic/campaigns/<campaign>/<run>/candidate.py`，修复另存 `candidate_repaired.py`；不改写已开启实验。`scripts/research/etf_autoresearch_candidate.py` 是旧接口候选/参考文件。每条返回 14 ETF 分数、事前方向、家族和公式说明。不能读取标签、未来日期或库存 IC 来构造分数，也不能修改来源数据；模块只接收 approved profile 中截至 D 可知的面板。
- **固定评价器**：`scripts/research/run_etf_autoresearch_ic.py`。固定人口、冷线 2026-03-24、评价起点 2025-01-01、D 收盘信息、D+2/H5 标签、八组聚合与原 `etf_group_discovery.evaluate` 的 signed Rank IC。代理不得逐轮编辑此文件、`etf_group_discovery.py`、`etf_rank_utils.py` 或原规则。
- **本地日志**：`runtime_outputs/etf_autoresearch_ic/attempts/<run_id>.json` 为每个调用记录最终状态，含预检、评价、查重或比较失败；`results.tsv` 另记完成评价的试验。全部留本地，不进入 Git。源数据仍为只读的本地 `etf_rotation_v1`，不上传。
- **全库查重**：每次评价后用 `scripts/research/audit_etf_autoresearch_novelty.py` 对本轮 `group_scores.csv` 与最新正式库存及本地历次试验的分数做截至冷线的无标签相关性。与旧定义高度重合时，保留 IC 记录，但不称新信息；缺失或共同有效日不足的旧分数单独列出。
- **正式登记**：试验循环不写正式 `runs/*/PLAN.json`，不改变 20 轮正式账本。`prepare_etf_autoresearch_promotion.py` 将经过审阅的试验提交中的唯一候选文件复制到不可变的 `autoresearch_frozen/`，生成原 runner 可读的配置和审阅包；master 审阅后仍由原 `discover_etf_groups.py` 按下一预算序号一次性登记。新入口固定 `SEEN_2026_ADAPTIVE_NOT_CONFIRMATION`，已反复看过的历史 IC 不被写成独立确认。

## 每次实验

1. 先决定是新家族 0→1，还是已有 IC 父因子的 1→10。后一种先冻结可复算的父因子基线；读前一轮代码、结果及累计试验日志，记录家族和近邻。
2. 只修改候选文件，写清公式、方向、家族。先保存不可变源码快照和哈希。评价阶段的五分钟预算超时则记失败；异常按失败阶段记入本地尝试账本。
3. 运行固定评价、全库查重及基线比较的一条命令：

   ```bash
   python frameworks/etf_rotation/scripts/research/cycle_etf_autoresearch.py \
     --run-id <唯一试验编号> \
     --baseline runtime_outputs/etf_autoresearch_ic/<固定父基线编号> \
     --parent-candidate <正式库父因子ID> \
     --inventory <最新完整本地库存>/all_factors.csv \
     --runs-root runtime_outputs/etf_rotation_research/runs
   ```

   新家族的 0→1 探索省略 `--parent-candidate`；这时 `--baseline` 仍须指向同一评价器下的固定参考试验。

4. 查看本地 `result.json`：完整逐日 IC、有符号均值、HAC t、块 t、有效日、分年 IC、代码和评价器哈希。不得只抄最好的数。与基线比较时，先看共同有效日期和覆盖；基线差值只供诊断，不是不同家族入库的必要条件。
5. 读自动产生的 `novelty.json` 与 `decision.json`。`decision` 只描述 signed IC 及覆盖：`positive_ic_review`、`weak_positive_ic`、`negative_ic_watch`、`zero_ic` 或 `uncomputable_ic`；重复度独立保存在 `novelty_diagnostic`。若最高平均绝对逐日八组秩相关达到现有 0.7 注记阈值，仍保留原 IC 数字，但不能称为独立新因子。`positive_ic_review` 不等于通过 HAC/块 t、累计预算或认证。
6. 所有结果保留试验日志与代码版本；代理根据证据把唯一候选文件恢复到选定基线或继续下一试验。负方向结果保留原值，不在相同结果上直接翻向。

当 master 认为一条 `positive_ic_review` 候选值得正式登记时，用试验代码的 Git 提交或 `--source-snapshot <候选快照>`、试验目录和当时最新本地库存执行 `prepare_etf_autoresearch_promotion.py`。高重合不抹掉 IC 线索，但审阅时要明确是否只是旧因子复写。审阅包列出本地已知试验数、正式库与本地近邻、试验 IC、代码/数据哈希、拟用的累计账本起点。审阅后按现有审批机制签发绑定源码的批准记录，再运行原 `discover_etf_groups.py`。任何正式运行前，必须重新核对 `prior_registered`，因为其他批次可能已先登记。

停止条件：完成用户授权的轮数、出现重复的模板搜索、源数据或时间检查失败，或用户叫停。不得通过改标签、人口、评价窗口、统计门槛或隐藏失败实验来提高结果。正式前向评价继续沿用月度 v4。
